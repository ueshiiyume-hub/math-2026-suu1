# プリント → 解説スライド

高校数学の先生（数学Ⅰ）の授業プリントを、生徒がスマホやPCで見る解説スライドにする作業の手順書。
スライドは1枚の HTML（外部ファイルなし）。←→ やクリックで1段ずつ進み、横長（1280×720）とスマホ縦長（720×1280）の両方に対応する。

## 部品（kit/）

このスキルのフォルダの `kit/` に、ここまで作った部品の写しがある。新しいフォルダで始めるときは、`kit/` の中身をそのフォルダの `_作成用/` にコピーして使う（tools/ は除いてよい）。
すでに `_作成用/` があるフォルダでは、そちらが最新なので、そちらを使う。

| ファイル | 役割 |
|---|---|
| head.html / extra.css | ページの土台と共通の見た目（方眼の背景、カード、マスキングテープ、色の札） |
| core.js | 共通の小道具：`M()`（式）`K(色,文字)`（色の札）`tm(色,文字,番)`（あとから色がつく）`S(番,html)`（出現）`slotC()`（空らん＋飛んでくる数）`ANS()`（答えの下線）`cbar(説明の配列)`（下の説明欄）`TP()`（テープ）。2次関数のグラフ・平方完成の部品もある |
| engine.js | 組み立てと操作。`data-s`（その番で出る）`data-o`（その番で色）`data-f`（その番で飛ぶ）`data-m`（説明の番）から段数を自動で数える。`layoutExtra(root)` があれば位置合わせで呼ぶ |
| kimatsu.js / kimatsu.css | 期末用の部品：`coverF` `endF`（表紙・おわり）、`patOverview`（パターン一覧）、`fxSlide`（因数分解：左に式、右に大きな考え方カード）、`tstep([問いの番,答えの番],…)`、`eqSlide`（2次方程式：青と橙の ( ) → ＝0 → 移項の矢印 → x＝） |
| build_kimatsu.py | 各プリントの「デッキ」（スライドの中身）を書くところ。`decks['ファイル名'] = (題, JS)` |
| versions.json | スライドごとの バージョン・日付・メモ。build が 表紙の 左下に 出す。直したら 毎回 上げる |
| menus.py / menu.html | 目次ページ（カードの一覧）を作る |
| build.py / words.js | 中間考査のときのデッキ（参考） |
| ink.js | 手書き（授業中に上から書きこむ）。右上の ✏ か W キー。赤・青・黒、消しゴム(E)、1つ戻す(Ctrl+Z)、全消し。線はスライドごとに台紙座標で保存。build_kimatsu.py が engine.js の後ろにつなげる |
| ptSlide（kimatsu.js） | プリントの 配置（PDF の pt 座標）どおりに 部品を 置く。画像は 使わない。T＝最初から 出ている 印刷部分、E＝クリックで 出る 部分。①-6 から この形 |
| decks_kimatsu2.py | ①-6〜③-4 の デッキ。`pgSlide`：プリントの その部分の 画像（`@@IMG:ページ:x1,y1,x2,y2@@` を build が PNG に 置きかえる。_作成用/print.pdf が 必要）を 背景に して、空らんの 座標に 答え（A）・マーカー（MK）・放物線（PB：塗る・白丸/黒丸）を 重ねる。画像が そのままで 見にくいと 言われたので 使わない（下書き用） |
| tools/shot.sh | 指定の場面を Chrome ヘッドレスで撮影 |
| tools/docx2png.ps1 | プリント(docx)を PDF → ページごとの PNG に |

## 置き場所

このスキルの 本体は GitHub（ueshiiyume-hub/math-2026-suu1 の `_作成用/skill/`）。部品は `_作成用/` に ある。パソコンの `~/.claude/skills/print-to-slides/` は その 写し。パソコンで 作業したら 両方 そろえる。

## 手順

1. **プリントをよく見る（必須）**：docx をそのまま読むと、枠や色の配置が分からない。`tools/docx2png.ps1` で画像にして、対象のページを Read で見る。必要なら fitz（PyMuPDF）で、その部分だけ高い解像度で切り出す。枠の色・並び・矢印・空らん・注意書きを、そのまま再現する。
2. **組み立て**：`build_kimatsu.py` にデッキを足す。形が同じ問題は部品（`eqSlide` など）にパラメータを渡すだけにする。新しい形が必要なら、kimatsu.js / kimatsu.css に部品を足す。スマホ用の並べかえは、engine.js の `kind()` にクラス名を足して、`.portrait .t-◯ …` の CSS を書く。
3. **作る**：`python _作成用/build_kimatsu.py <出力フォルダ>` → `python _作成用/menus.py .`（目次にカードを足すときは menus.py を書きかえる）。
4. **撮影して確かめる（毎回）**：`OUTDIR=<scratchpad>/shot bash tools/shot.sh <html> 1280 720 1-0 1-e 2-3 …` と `… 540 960 …`。重なり・はみ出し・文字の高さのずれを見る。真っ白になったら JS のエラー（コメントの閉じ忘れなど）を疑う。
5. **先生に見せる** → 直しの指示はスクリーンショット付きで細かく来る。1つずつ直して、また撮影する。
6. **プッシュ**：そのフォルダの CLAUDE.md の決まりに従う（70_web教材 では、直すたびに自動でプッシュ）。プッシュしたら、公開URLが 200 を返すまで curl で待って確かめる。

## 先生のデザインの好み（守ること）

- **文字は最小限**。カードの見出しは短い問いかけ（「かけて 15 に なる数は？」「共通なのは？」）。補足の行や「たしかめ（展開して元に戻る）」は入れない。
- **文字の公式（a, b を使った公式）は出さない**。実際の式で、注目する数に色を付け、キーワードを1行だけ。
- **プリントのレイアウトに合わせる**（青と橙の ( ) の枠、x＝ の枠、重解の赤い枠、※注意 の枠など）。
- **実際の頭の中の考え方を見せる**：例「符号は気にせず 3×5 が浮かぶ → 差が 2 → 符号を調整」。教科書どおりの全部の組の書き出しはしない。
- **1クリックで1つ**。問い → 次のクリックで答え。矢印（「因数分解」「移項」）がアニメーションで出てから、次のクリック（または少し遅れて）結果が出る。
- **移項**：「x ＋ 5 ＝ 0」→ ＋5 から −5 へ矢印 → 「x ＝ −5」。＝ の縦の位置をそろえ、x と ＝ の間に隙間を作らない。
- **一覧・まとめのページはアニメーションなし**で、式を大きく、すっきり。
- **下の説明欄＝「なぜ」を言葉で**、カード＝式だけ。同じことをくり返さない。説明は1〜2行。
- **プリントの 配置を 縮小して 並べる 作り方も 見にくい**（文字が 小さい）。1枚に 1つの ことを 大きく（式 40px 前後、文字 28px 以上）、①-1〜①-5 のように 工夫する。プリントとの 対応は 色（b² 緑・−4ac オレンジ・D 青 など）と 並び順で とる。
- 内容の「行間」を 語る：なぜ そうなるか（例：個数を 決めるのは ルートの中だけ → だから 解を 求めなくていい → 判別式）。いきなり 作らず、まず 流れを 提案して 了承を もらう。
- 2次不等式（③-1〜）の 教え方：x軸＝水面。「息が できるのは どこ？」。＞・≧ は 上が すきな 鳥号（空で 息が できる）、＜・≦ は 下が すきな 魚号（水の中で 息が できる）が 左から レール（放物線）を 進み、息が できない ところは くるしい 顔で 通る（毒ガス などの こわい 言葉は 使わない）。良い ところを 左から 順に 塗る。y＝0 の 点は ＞ なら 塗れない 白丸（その先を 塗る）、≧ なら 黒丸。答えは x軸に 影を 落とさず、塗れた 部分に x を 置いて −1 や 3 と 比べる（左の x ＜ −1、3 ＜ 右の x）。白丸 → ＜、黒丸 → ≦。確かめの 点を いくつも 取る 説明は しない。
- 放物線は しゅっと（②-1 くらいの 細さ）。
- 2次方程式で ルートの中が マイナスのときは「解なし」と書く（「実数解なし」とは書かない）。
- 教え方の決まり：x²＋6x＋9 は「たして・かけて → 同じ ( ) が2つ → 2乗にまとめる」。2次方程式では (x＋3)(x＋3)＝0 → −3, −3 と書いてから1つにまとめて「重解」。x(x＋6)＝0 は ( ) の方を先に解き、x＝0 はあとで。
- 「OK」などの英字は、自動で数式の斜体になるので説明文に使わない。

## 技術メモ

- flex の箱の中に文字を直接入れると、文字ごとに上下中央にそろえられて高さがずれる → 中身を `<span>` で包む。
- `.r` / `.lh` は出現のときに `transform` を上書きするので、回転させたいものは内側の要素に回転を付ける。
- 飛んでくる数（`slotC` の `data-src`）は、同じスライド内の `data-k` を探して出発点にする。
- 段数は `data-*` の最大値から決まる。説明の配列（cbar）の数と、最後の番を合わせる。
- プリントに書きこむ形のページ（①-4 解の公式など）は、PDF の枠の座標（fitz の get_drawings）を そのまま 拡大して 置く（`kfSlide`）。生徒がプリントのどこに書くか 迷わないよう、枠の位置・形は 変えない。
- `@@IMG…@@` は JS が 動く前に 置きかえるので、JS の 変数で 組み立てない（文字列を そのまま 書く）。
- 印刷された グラフに 塗るときは、画像から 放物線（頂点・根・上端）を 読み取って PB の xv・yv・q を 合わせる（draw:false）。
- engine.js の 最初の render() は ink.js より前に 走るので、ink.js の 変数は var で 宣言する（const だと 読み込み時に エラー）。
- ルートは `SQ()`（kimatsu.js）で 書く。√ を SVG で かいて 上の 線と つなげている（文字の √ だと 線と ずれる）。線の 太さは `--rw`。
- ②-1 から：`GR()`（グラフ：x軸＋下に凸の 放物線、点・文字・かく番）、`XR()`（右の x座標・個数の 欄）、`GA()`（緑の 矢印）は decks_kimatsu2.py の ②-1 に ある。点の 下の 文字が 放物線と 重なるときは `lo` で 外側に ずらす。
- 撮影で アニメーションの 途中が 写るときは `FINAL=1` を つける（最後の 形で 撮る）。
- 撮影は Windows でも クラウド（Linux、/opt/pw-browsers の chromium）でも `tools/shot.sh` で できる。
- 新しいスライドを作る前に、そのフォルダの CLAUDE.md（サイト固有の決まり）を読む。
